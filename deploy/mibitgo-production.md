## Fresh database initialization

`Seed__DemoData=false` selects essential seeding: one administrator, territory reference data, brand settings, and access groups. Existing sites retain their previous seeding behavior unless explicitly configured otherwise. The generated initial administrator password is held only in the protected environment as `Seed__AdminPassword`; the admin phone is `09000000000`. It is used only when there is no administrator, and does not reset an existing password.

Mibitgo has its own JWT key and issuer/audience, Mibitgo-only CORS origins, and a simple Mibitgo logo/favicon. Google settings initially inherit YaPasakay's configuration; Google Cloud origin authorization and complete browser sign-in require independent verification. No mobile application identity or release is created.

## Provisioning and recovery

`provision-mibitgo.py` runs on the server with the installed SiteTools worker library. `prepare` checks collisions and creates resources from a reviewed bootstrap artifact. It refuses to run again once progress exists. `web` validates the fresh database before exposing HTTPS. `register <commit>` checks production release metadata before adding SiteLogs mappings. Progress is root-only at `/var/lib/sitetools-provision/mibitgo-progress.json`.

Failures retain partial resources for diagnosis. Do not rerun creation or restore over an existing database. The helper coordinates with the idle provisioning daemon and restarts it in a finally block. Live release verification is recorded in the progress file and `/var/lib/mibitgo/release.json`.
