## Build again

Build toolchain: Flutter 3.44.9 / Dart 3.12.2 and Java 17. The dependency lockfile is resolved for that SDK. Install Flutter and the Android SDK. Create `android/local.properties` with your own `flutter.sdk` and `sdk.dir` paths and the authorized `MAPS_API_KEY`, or supply the Maps key through an environment variable. Use forward slashes in Windows paths.

Create ignored `android/key.properties`:

```properties
storeFile=../releases/1.0.0/trygoride-passenger-upload.p12
storePassword=YOUR_PRIVATE_PASSWORD
keyAlias=trygoride-passenger-upload
keyPassword=YOUR_PRIVATE_PASSWORD
```

Run `powershell -ExecutionPolicy Bypass -File scripts/build-play-release.ps1` from this app directory. The script uses the local shared mobile tools when present, otherwise Flutter from PATH. Increase the version code for every subsequent Play upload.

To verify the finished artifact, download Google's official `bundletool-all` jar and run `powershell -ExecutionPolicy Bypass -File scripts/verify-play-release.ps1 -Bundletool PATH_TO_JAR`. This checks the bundle structure, signature, upload certificate match, package, version, label, release mode, Maps key presence and checksum without printing the Maps key.

## Google Play handoff

Create the Play listing for this package, enable Google-managed Play App Signing, and upload the AAB to an internal testing release. The included certificate identifies the upload key. Google Play creates/manages a separate distribution signing key; its certificate is available in Play Console after enrollment and is not generated by this local build.

The owner requested use of TryGoRide's web Maps key. Before publishing, verify Maps SDK for Android is enabled and the key restrictions permit `com.trygoride.passenger` with the Play app-signing certificate SHA-1. Register the same package and Play SHA-1 in the correct Google OAuth project for native Google sign-in. The upload certificate fingerprint alone does not cover Play-installed builds. Test Maps, Google login, booking and notifications using the Play internal-test installation.

Local build/signature checks do not prove Google Cloud configuration or Play Console acceptance. No Play Store upload or publication is performed by the build script.
